# Translating the user interface

`antwika::i18n` is the library every user-visible string goes through.
It depends on nothing — not `gfx`, not `ui`, not `event`, not `replay` — because a translation is a fact about text, not about how the text is drawn or when it is asked for.
The catalogues are compiled in rather than loaded, which is the same rule the rest of the project follows: a library under `src/libs/` opens no files, so nothing a user can rename or corrupt can change what a run does.

## A message is named, not quoted

A catalogue is keyed by `i18n::MessageId` — `MenuPlayGame`, `ToolbarResetView` — and never by the English text.
Keying by the English text is the usual shortcut, and it has one failure that cannot be fixed afterwards: a locale that is missing an entry falls through to the key, which *is* readable English prose, so a missing translation and a finished one are the same thing at runtime.
Nobody can see the gap, no test can assert its absence, and the English original stays embedded in the calling code where a translator will never find it.

With a symbolic key the gap is a value.
`kAllMessageIds` names every string the program can show, so `CatalogueTest.CatalogueFor_CoversExactlyTheSameIdSetInEveryLocale` can compare the id set of the English catalogue against the Swedish one and fail if either has drifted.
That test is the whole return on the design: adding an eleventh message and forgetting the Swedish text is a red build rather than an English label in a Swedish menu.
`Locale`, likewise, is a closed enum with a language tag (`en`, `sv`) rather than an open tag string, because every locale the library answers for has a catalogue compiled into it — an unrecognised tag is a parse failure at the edge in `localeFromTag()` rather than an empty catalogue in the middle.

The language names are themselves messages, reached through `nameIdOf()`.
A language picker therefore reads them through the *active* translator, and reads "English"/"Swedish" while English is on and "Engelska"/"Svenska" while Swedish is.
Showing every language under its own endonym instead is a change of catalogue data, not of code.

## Lookup is total, and says so

`i18n::lookup()` never throws.
It asks the active catalogue, then the fallback catalogue, and resolves an id neither knows to that id's own name in exclamation marks — `"!MenuSaveReplay!"`.
Throwing was rejected because a lookup happens while a frame is being drawn: a missing translation would then take the program down in front of the user, and the one thing worse than a wrong label is no window.

Falling back silently was rejected for the reason the symbolic key exists at all, so the miss is reported rather than swallowed.
Every lookup returns an `i18n::Translation`, whose `origin` is one of three values:

- `TranslationOrigin::Exact` — the active locale's own catalogue answered.
- `TranslationOrigin::Fallback` — the active locale was silent and the default locale (`kDefaultLocale`, English) answered.
- `TranslationOrigin::Missing` — neither answered, and the text is the id's name in exclamation marks.

A caller that only wants to draw something calls `Translator::text()` and ignores all of this.
A test that wants to insist a locale is complete asserts `TranslationOrigin::Exact`, which prose alone could not express, since a genuine translation and a fallback can read identically.
The exclamation marks are deliberate: a gap should be something somebody notices in a screenshot, not a label that merely looks short.

An unknown `Locale` follows the same rule one step earlier — `catalogueFor()` hands back the default locale's catalogue, and `nameIdOf()` the default locale's name id, rather than refusing.

## Arguments are positional

`substitute()` replaces `{0}`, `{1}` and so on with arguments supplied by index, and `format()` does a lookup and a substitution together.
Positional rather than named, because argument *order* is the one thing a translator legitimately changes, and `{0}` lets the catalogue say so without the calling code knowing.
`ToolbarZoomLevel` is the worked example: `"zoom {0}"` in both catalogues today, but nothing outside the catalogue would have to change if a language wanted the number first.

Substitution is total for the same reason lookup is.
A `{` that does not open a run of decimal digits closed by `}`, or that names an argument nobody supplied, is copied out as written, so a mis-numbered placeholder is visible in the text rather than silently blank.
A literal `{0}` is therefore not expressible; no message needs one, and an escape would be a second rule to learn for a case that has not come up.

## What is not here

There is no plural rule, no gender agreement, no date or number formatting and no locale-aware collation.
None of the strings the interface has today needs any of it, and each would be a body of rules that has to be right for every locale rather than a facility that can be added per string.

The Swedish catalogue is UTF-8 and contains `å`, `ä` and `ö`.
Whether those glyphs reach the screen is a question for whatever draws the text, not for this library, which deals only in bytes.
